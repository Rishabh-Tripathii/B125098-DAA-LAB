# Coin Change: Total Number of Ways

## Problem Statement

Given an array of distinct positive integers representing coin denominations:

```text
C = {c1, c2, ..., cn}
```

and a target amount `V`, find the **total number of distinct combinations** of coins that sum up to `V`.

There is an infinite supply of each coin denomination.

The order of coins does not matter. Therefore, combinations that contain the same coins in a different order are considered the same.

---

## Approach

The problem is solved using **Dynamic Programming**.

Define:

```text
dp[x] = number of distinct combinations that can form amount x
```

The solution is constructed from smaller amounts to larger amounts.

The base condition is:

```text
dp[0] = 1
```

There is exactly one way to form an amount of `0`: selecting no coins.

Initially, all other values of `dp` are set to `0`.

For every coin denomination, we consider all amounts that can be formed using that coin and update the corresponding DP value.

---

## Recurrence Relation

For each coin `c` and amount `x` such that `c <= x`:

$$
dp[x] = dp[x] + dp[x-c]
$$

or:

$$
\boxed{dp[x] += dp[x-c]}
$$

Here:

* `dp[x-c]` represents the number of ways to form the remaining amount.
* Adding coin `c` to each of those combinations produces combinations for amount `x`.

---

## Algorithm

1. Create a DP array `dp[0...V]`.

2. Initialize every element of the array to `0`.

3. Set `dp[0] = 1`.

4. Process each coin denomination one at a time.

5. For each coin `c`, iterate through amounts from `c` to `V`.

6. For every amount `x`, update:

   $$
   dp[x] = dp[x] + dp[x-c]
   $$

7. After all denominations have been processed, `dp[V]` contains the total number of distinct combinations.

---

## Important Observation

The **order of processing** is important because the problem asks for combinations rather than permutations.

The coins are processed in the outer loop, while the amounts are processed in the inner loop.

This ensures that different arrangements of the same coins are not counted as separate solutions.

Thus:

```text
Coin loop
    ↓
Amount loop
```

is used to count distinct combinations.

---

## Correctness

The algorithm maintains the invariant that after processing the first `i` coin denominations, `dp[x]` represents the number of distinct combinations that form amount `x` using only those `i` denominations.

When a new coin `c` is processed, every existing combination for `x-c` can be extended by adding coin `c`. Therefore, `dp[x-c]` new combinations are added to `dp[x]`.

Since each denomination is introduced in a fixed order, every combination is counted exactly once.

Therefore, after processing all denominations, `dp[V]` gives the total number of distinct combinations that form the target amount `V`.

---

## Complexity Analysis

Let:

* `n` = number of coin denominations
* `V` = target amount

The algorithm processes every coin denomination and, for each coin, iterates through the possible amounts up to `V`.

### Time Complexity

$$
\boxed{O(nV)}
$$

### Space Complexity

The algorithm uses a one-dimensional DP array of size `V + 1`.

$$
\boxed{O(V)}
$$

---

## Complexity Summary

| Resource | Complexity |
| -------- | ---------- |
| Time     | **O(nV)**  |
| Space    | **O(V)**   |

---

## Key Points

* Uses **Dynamic Programming**.
* Allows an **infinite supply** of each coin.
* Counts **combinations**, not permutations.
* The base case is `dp[0] = 1`.
* The recurrence is:

$$
\boxed{dp[x] += dp[x-c]}
$$

* Coin denominations are processed before amounts.
* Time complexity: **O(nV)**.
* Space complexity: **O(V)**.
