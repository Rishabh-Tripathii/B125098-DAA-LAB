# Minimum Coin Change

## Problem Statement

Given an array of coin denominations `C = {c1, c2, ..., cn}` and a target amount `V`, find the **minimum number of coins** required to make the target amount.

There is an **infinite supply** of each type of coin.

If the target amount cannot be formed using the given denominations, return `-1`.

### Example

```text
Coins = {1, 3, 4}
Target = 6
```

Possible combinations:

```text
1 + 1 + 1 + 1 + 1 + 1 = 6   → 6 coins
3 + 3 = 6                   → 2 coins
4 + 1 + 1 = 6               → 3 coins
```

Therefore:

```text
Answer = 2
```

---

## Approach

We solve this problem using **Dynamic Programming (DP)**.

The main idea is to solve the problem for smaller amounts first and use those results to solve larger amounts.

Define:

```text
dp[x] = minimum number of coins required to make amount x
```

### Base Case

To make an amount of `0`, we need `0` coins.

```text
dp[0] = 0
```

For all other amounts, initially assume that they cannot be formed.

---

## Recurrence Relation

For every amount `x`, try every coin `c`.

If:

```text
c <= x
```

then after choosing coin `c`, the remaining amount is:

```text
x - c
```

We already know the minimum number of coins required for `x - c`, which is:

```text
dp[x - c]
```

Adding the current coin gives:

```text
dp[x - c] + 1
```

Therefore:

```text
dp[x] = min(dp[x], dp[x - c] + 1)
```

For all denominations:

```text
dp[x] = min(dp[x - ci] + 1)
```

where `ci <= x`.

---

## Algorithm

1. Create an array `dp` of size `V + 1`.
2. Set `dp[0] = 0`.
3. Initialize all other `dp` values to a large value representing infinity.
4. For every amount from `1` to `V`:

   * Iterate through every coin denomination.
   * If the coin value is less than or equal to the current amount:

     * Calculate `dp[amount - coin] + 1`.
     * Take the minimum with the current value of `dp[amount]`.
5. After filling the DP table:

   * If `dp[V]` is still infinity, return `-1`.
   * Otherwise, return `dp[V]`.

---

## Pseudocode

```text
MINIMUM-COINS(coins, n, V)

    create dp[0 ... V]

    dp[0] = 0

    for amount = 1 to V
        dp[amount] = infinity

    for amount = 1 to V

        for each coin in coins

            if coin <= amount

                dp[amount] =
                    min(dp[amount],
                        dp[amount - coin] + 1)

    if dp[V] == infinity
        return -1

    return dp[V]
```

## Example Walkthrough

Consider:

```text
Coins = {1, 3, 4}
V = 6
```

The DP table is built as follows:

| Amount | 0 | 1 | 2 | 3 | 4 | 5 | 6     |
| ------ | - | - | - | - | - | - | ----- |
| `dp`   | 0 | 1 | 2 | 1 | 1 | 2 | **2** |

For `amount = 6`:

Using coin `1`:

```text
dp[6] = dp[5] + 1
      = 2 + 1
      = 3
```

Using coin `3`:

```text
dp[6] = dp[3] + 1
      = 1 + 1
      = 2
```

Using coin `4`:

```text
dp[6] = dp[2] + 1
      = 2 + 1
      = 3
```

Take the minimum:

```text
min(3, 2, 3) = 2
```

Therefore:

```text
Minimum number of coins = 2
```

The optimal combination is:

```text
3 + 3 = 6
```

## Why Dynamic Programming?

This problem has two important properties.

### 1. Optimal Substructure

The optimal solution for an amount depends on optimal solutions of smaller amounts.

For example, to find the minimum coins for `6` using coin `3`, we need the minimum coins for:

```text
6 - 3 = 3
```

Since `dp[3]` has already been calculated, we can use it directly.

### 2. Overlapping Subproblems

The same smaller amounts can be needed multiple times.

For example, `dp[3]` may be required while calculating several larger amounts.

Instead of calculating it repeatedly, Dynamic Programming stores the result in the `dp` array.

---

## Complexity Analysis

Let:

* `n` = number of coin denominations
* `V` = target amount

There are `V` different amounts to calculate.

For each amount, we check all `n` coins.

Therefore:

### Time Complexity

```text
O(n × V)
```

### Space Complexity

The DP array contains `V + 1` elements.

```text
O(V)
```

Therefore:

| Complexity | Value      |
| ---------- | ---------- |
| Time       | `O(n × V)` |
| Space      | `O(V)`     |

---

## Handling Impossible Cases

Suppose:

```text
Coins = {2, 4}
V = 7
```

All available coins are even, so it is impossible to make `7`.

The algorithm returns:

```text
-1
```

## Summary

The core idea is:

```text
dp[x] = minimum coins needed to make x
```

For every amount, try every coin:

```text
dp[x] = min(dp[x], dp[x - coin] + 1)
```

Finally:

```text
dp[V]
```

gives the minimum number of coins required to make the target amount.

If `dp[V]` remains infinity, the target cannot be formed and the algorithm returns:

```text
-1
```
