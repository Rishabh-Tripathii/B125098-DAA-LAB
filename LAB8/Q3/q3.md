# Longest Common Subsequence (LCS)

## Problem Statement

Given two sequences:

```text
X = {x1, x2, ..., xm}
Y = {y1, y2, ..., yn}
```

find:

1. The **length of the Longest Common Subsequence (LCS)**.
2. The **actual LCS string**.

A subsequence is obtained by deleting zero or more elements from a sequence without changing the order of the remaining elements.

The elements of the subsequence do not need to be contiguous.

---

## Approach

The problem is solved using **Dynamic Programming**.

Define:

```text
dp[i][j]
```

as the length of the LCS between:

```text
X[0 ... i-1]
```

and:

```text
Y[0 ... j-1]
```

The DP table is built from smaller prefixes of the two sequences.

---

## Base Case

If either sequence is empty, there is no common subsequence.

Therefore:

```text
dp[0][j] = 0
dp[i][0] = 0
```

for all valid `i` and `j`.

---

## Recurrence Relation

There are two cases.

### Case 1: Characters Match

If:

```text
X[i-1] == Y[j-1]
```

then the matching character can be included in the LCS.

Therefore:

$$
dp[i][j] = dp[i-1][j-1] + 1
$$

### Case 2: Characters Do Not Match

If:

```text
X[i-1] != Y[j-1]
```

the two characters cannot both be the last character of the same common subsequence.

We consider two possibilities:

* Exclude `X[i-1]`
* Exclude `Y[j-1]`

Therefore:

$$
dp[i][j] = \max(dp[i-1][j], dp[i][j-1])
$$

The complete recurrence is:

$$
dp[i][j] =
\begin{cases}
dp[i-1][j-1] + 1, & X[i-1] = Y[j-1] \\
\max(dp[i-1][j], dp[i][j-1]), & X[i-1] \neq Y[j-1]
\end{cases}
$$

---

## Algorithm

1. Create a two-dimensional DP table of size `(m + 1) × (n + 1)`.
2. Initialize the first row and first column to `0`.
3. Iterate through both sequences.
4. If the current characters are equal:

   * Set `dp[i][j] = dp[i-1][j-1] + 1`.
5. Otherwise:

   * Set `dp[i][j]` to the maximum of `dp[i-1][j]` and `dp[i][j-1]`.
6. After filling the table, `dp[m][n]` gives the length of the LCS.
7. To reconstruct the actual LCS, start from `dp[m][n]` and trace backward through the table.
8. When the characters match, add that character to the LCS and move diagonally.
9. When they do not match, move toward the neighboring cell with the larger DP value.
10. Since the characters are collected from the end to the beginning, reverse the reconstructed sequence.

---

## LCS Reconstruction

The actual subsequence is reconstructed by starting at:

```text
dp[m][n]
```

and moving toward:

```text
dp[0][0]
```

### If characters match

If:

```text
X[i-1] == Y[j-1]
```

then:

```text
X[i-1]
```

is included in the LCS.

Move diagonally:

```text
(i, j) → (i-1, j-1)
```

### If characters do not match

Compare:

```text
dp[i-1][j]
```

and:

```text
dp[i][j-1]
```

Move to the cell containing the larger value.

Continue until either `i = 0` or `j = 0`.

The collected characters are in reverse order, so they must be reversed to obtain the final LCS.

---

## Correctness

The algorithm correctly considers all possible common subsequences through the following cases:

* When the current elements match, including that element extends the LCS of the two previous prefixes.
* When the current elements do not match, an optimal LCS must exclude at least one of the two elements. Taking the maximum of the two resulting subproblems therefore preserves the optimal solution.

Thus, `dp[i][j]` stores the length of the LCS for every pair of prefixes.

The final value:

```text
dp[m][n]
```

is therefore the length of the LCS of the complete sequences.

Tracing the DP table backward reconstructs one valid LCS of maximum length.

---

## Complexity Analysis

Let:

* `m` = length of the first sequence
* `n` = length of the second sequence

The DP table contains:

```text
(m + 1) × (n + 1)
```

entries.

Each entry requires constant time to calculate.

### Time Complexity

$$
\boxed{O(mn)}
$$

### Space Complexity

The two-dimensional DP table requires:

$$
\boxed{O(mn)}
$$

Additional space is required to store the reconstructed LCS, but this does not change the overall asymptotic complexity because the DP table dominates.

---

## Complexity Summary

| Resource      | Complexity |
| ------------- | ---------- |
| Time          | **O(mn)**  |
| DP Space      | **O(mn)**  |
| Overall Space | **O(mn)**  |

---

## Key Points

* LCS is solved efficiently using **Dynamic Programming**.
* `dp[i][j]` stores the LCS length for two prefixes.
* Matching elements use the **diagonal value + 1**.
* Non-matching elements use the **maximum of the upper and left values**.
* The actual LCS is reconstructed by tracing the DP table backward.
* Time complexity: **O(mn)**.
* Space complexity: **O(mn)**.
