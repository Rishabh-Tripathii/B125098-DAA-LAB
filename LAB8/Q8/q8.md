# Optimal Binary Search Tree (OBST)

## Approach

The problem is solved using **Dynamic Programming**.

Let:

- `p[i]` = probability of a successful search for key `k[i]`
- `q[i]` = probability of an unsuccessful search for dummy key `d[i]`
- `cost[i][j]` = minimum expected search cost for keys `k[i]` through `k[j]`
- `weight[i][j]` = total probability associated with the subtree
- `root[i][j]` = key selected as the root of the optimal subtree

For an interval `[i, j]`, every key from `i` to `j` is considered as a possible root.

The recurrence is:

\[
cost[i][j]
=
weight[i][j]
+
\min_{i\le r\le j}
\left(cost[i][r-1]+cost[r+1][j]\right)
\]

where:

\[
weight[i][j]
=
\sum_{k=i}^{j}p[k]
+
\sum_{k=i-1}^{j}q[k]
\]

The base case for an empty subtree is:

\[
cost[i][i-1] = q[i-1]
\]

The `root[][]` table stores the root that produces the minimum expected search cost, allowing the optimal BST to be reconstructed.

## Algorithm

1. Read the number of keys `n`.
2. Read the successful search probabilities `p[1...n]`.
3. Read the unsuccessful search probabilities `q[0...n]`.
4. Initialize the cost and weight of empty subtrees:
   \[
   cost[i][i-1] = weight[i][i-1] = q[i-1]
   \]
5. Consider subtrees in increasing order of their length.
6. For every interval `[i, j]`:
   - Calculate `weight[i][j]`.
   - Try every key `r` from `i` to `j` as the root.
   - Calculate:
     \[
     currentCost =
     cost[i][r-1] +
     cost[r+1][j] +
     weight[i][j]
     \]
   - Select the root that gives the minimum cost.
   - Store the selected root in `root[i][j]`.
7. `cost[1][n]` gives the minimum expected search cost.
8. Use the `root[][]` table recursively to reconstruct the optimal binary search tree.

## Complexity Analysis

### Time Complexity

There are `O(n²)` possible intervals of keys.

For each interval, every possible key within the interval is considered as a root, requiring up to `O(n)` operations.

Therefore:

\[
\boxed{O(n^3)}
\]

The computation of the probability weights takes `O(n²)` time and does not change the overall complexity.

### Space Complexity

The following two-dimensional tables are maintained:

- `cost[][]` → `O(n²)`
- `weight[][]` → `O(n²)`
- `root[][]` → `O(n²)`

Therefore:

\[
\boxed{O(n^2)}
\]

## Final Complexity

| Complexity | Value |
|------------|-------|
| Time | **O(n³)** |
| Space | **O(n²)** |
