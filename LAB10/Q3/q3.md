# Maximum Weight Component with Size Constraints

## Problem
Given a graph in which each vertex \(v\) has a weight \(w_v\), edges are added sequentially. After each edge insertion, find the maximum total vertex weight among all connected components containing at most \(K\) vertices.

The total weight of a connected component is the sum of the weights of all its vertices. A component is valid if its number of vertices does not exceed \(K\).

## Approach
Use the **Disjoint Set Union (DSU)** data structure to maintain connected components efficiently. DSU supports merging two components and finding the representative of a component.

For each component, maintain:
- **Parent:** Representative of the component.
- **Size:** Number of vertices in the component.
- **Weight:** Sum of the weights of all vertices in the component.

Initially, every vertex forms an individual component. When a new edge is added, find the roots of its endpoints. If the roots differ, merge the components using union by size and update their total size and weight.

After each insertion, examine the components and find the maximum weight among those whose size is at most \(K\).

Path compression and union by size optimize DSU operations.

## Algorithm
1. Read the number of vertices \(n\), edges \(m\), and size constraint \(K\).
2. Initialize each vertex as its own parent, with size \(1\) and its given weight.
3. For each edge \((u,v)\):
   - Find the roots of \(u\) and \(v\).
   - If their roots are different, merge their components using union by size.
   - Update the size and total weight of the merged component.
   - Traverse all vertices to identify component roots.
   - Consider only components whose size is at most \(K\).
   - Find and print the maximum weight among these valid components.
4. Repeat until all edges have been processed.

## Complexity Analysis
Let \(n\) be the number of vertices and \(m\) the number of edges.

- **Time Complexity:** \(O(nm)\), since each edge insertion is followed by a scan of all vertices. DSU operations take nearly constant amortized time, \(O(\alpha(n))\).
- **Space Complexity:** \(O(n)\), for the parent, size, and component-weight arrays.

Here, \(\alpha(n)\) is the inverse Ackermann function, which grows extremely slowly.
