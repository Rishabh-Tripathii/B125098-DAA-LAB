# Reverse Time-Step DSU Application

## Problem
Given an undirected graph with weighted vertices, vertices are deleted sequentially according to a given order \(P=[p_1,p_2,\ldots,p_V]\). After each deletion, determine the maximum sum of vertex weights among all remaining connected components.

When a vertex is deleted, all its incident edges are also removed. This may split a connected component into multiple smaller components, making direct deletion difficult to handle efficiently with Disjoint Set Union (DSU).

## Approach
Use **Reverse Time Processing with Disjoint Set Union (DSU)**.

Instead of processing deletions directly, process the vertices in reverse deletion order. This transforms deletions into activations, allowing DSU to maintain connected components efficiently.

Maintain the following information:
- **Parent:** Representative of each component.
- **Size:** Number of vertices in each component.
- **Sum:** Total vertex weight of each component.
- **Active:** Whether a vertex is currently present in the graph.

Initially, all vertices are inactive. Activate vertices in reverse order, merging each newly activated vertex with its active neighbours. Update component weights after every successful merge and maintain the maximum component weight.

Store the result for each reverse-processing step and output the answers in the original deletion order.

## Algorithm
1. Read the number of vertices \(V\), edges \(E\), vertex weights, graph edges, and deletion order.
2. Build an adjacency list for the undirected graph.
3. Initialize all vertices as inactive.
4. Process the deletion order from last to first:
   - Activate the current vertex.
   - Initialize its DSU component with size one and its own vertex weight.
   - Examine all adjacent vertices.
   - For each active neighbour, merge the two components if they have different roots.
   - Update the component weight and the maximum component weight.
   - Store the result for the corresponding deletion step.
5. Print the stored answers in the original deletion order.

## Complexity Analysis
Let \(V\) be the number of vertices and \(E\) be the number of edges.

- **Graph Construction:** \(O(V+E)\)
- **DSU Processing:** \(O((V+E)\alpha(V))\) amortized.
- **Total Time Complexity:** \(O(V+E\alpha(V))\).
- **Space Complexity:** \(O(V+E)\), for the adjacency list, DSU arrays, vertex weights, deletion order, and stored answers.

Here, \(\alpha(V)\) is the inverse Ackermann function, which grows extremely slowly.
