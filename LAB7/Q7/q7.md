# Matrix Chain Multiplication (MCM)

## Problem

Given a sequence of matrices:

    A1 × A2 × A3 × ... × An

where the dimensions of the matrices are known, determine:

1. The **minimum number of scalar multiplications** required to multiply all matrices.
2. The **optimal parenthesization (ordering)** that achieves this minimum cost.

Matrix multiplication is associative, meaning:

    (A × B) × C = A × (B × C)

However, different parenthesizations can require significantly different numbers of scalar multiplications.

The goal is therefore to find the ordering with the minimum multiplication cost.

---
## Example

Consider three matrices:

    A1 = 10 × 20
    A2 = 20 × 30
    A3 = 30 × 40

There are two possible parenthesizations:

    (A1 × A2) × A3

and

    A1 × (A2 × A3)

### Option 1

First multiply `A1 × A2`:

    10 × 20 × 30 = 6000

The resulting matrix is `10 × 30`.

Then multiply with `A3`:

    10 × 30 × 40 = 12000

Total:

    6000 + 12000 = 18000

### Option 2

First multiply `A2 × A3`:

    20 × 30 × 40 = 24000

The resulting matrix is `20 × 40`.

Then multiply with `A1`:

    10 × 20 × 40 = 8000

Total:

    24000 + 8000 = 32000

Therefore, the optimal ordering is:

    (A1 × A2) × A3

with:

    Minimum scalar multiplications = 18000

---

## Approach

This problem is solved using **Dynamic Programming (DP)**.

The main observation is that the optimal solution to a matrix chain contains optimal solutions to smaller matrix chains.

Let the matrices be:

    A1, A2, ..., An

Suppose the dimensions are stored in an array `p` such that:

    Ai has dimensions p[i-1] × p[i]

For example:

    A1 = 10 × 20
    A2 = 20 × 30
    A3 = 30 × 40

Then:

    p = [10, 20, 30, 40]

---

## DP State

Define:

    m[i][j]

as the minimum number of scalar multiplications required to multiply:

    Ai × Ai+1 × ... × Aj

For a single matrix:

    m[i][i] = 0

because no multiplication is required.

---

## Recurrence Relation

To multiply:

    Ai × Ai+1 × ... × Aj

we can split the chain at any position `k`:

    (Ai ... Ak) × (A(k+1) ... Aj)

where:

    i ≤ k < j

The cost consists of three parts:

1. Cost of multiplying the left subchain.
2. Cost of multiplying the right subchain.
3. Cost of multiplying the two resulting matrices.

Therefore:

    m[i][j] =
        min over i ≤ k < j of
        {
            m[i][k] +
            m[k+1][j] +
            p[i-1] × p[k] × p[j]
        }

The third term represents the scalar multiplications required to multiply the two resulting matrices.

---

## Storing the Optimal Ordering

Finding only the minimum cost is not enough because the problem also asks for the corresponding ordering.

Therefore, maintain another table:

    s[i][j]

where `s[i][j]` stores the value of `k` at which the optimal split occurs.

For example:

    s[1][4] = 2

means that the optimal multiplication of:

    A1 × A2 × A3 × A4

is split as:

    (A1 × A2) × (A3 × A4)

The `s` table can then be used to reconstruct the optimal parenthesization.

---

## Algorithm

1. Read the number of matrices `n`.
2. Read the dimension array `p`.
3. Initialize:
   
       m[i][i] = 0

   for every matrix.
4. Consider chains of length 2, then 3, and so on up to `n`.
5. For every subchain `Ai ... Aj`:
   - Try every possible split `k`.
   - Calculate:
   
       cost = m[i][k] + m[k+1][j]
              + p[i-1] * p[k] * p[j]

   - Choose the split with minimum cost.
6. Store the minimum cost in `m[i][j]`.
7. Store the corresponding split position in `s[i][j]`.
8. Finally, use the `s` table recursively to print the optimal parenthesization.

---

## Pseudocode

    MatrixChainOrder(p, n):

        for i = 1 to n:
            m[i][i] = 0

        for length = 2 to n:

            for i = 1 to n - length + 1:

                j = i + length - 1
                m[i][j] = infinity

                for k = i to j - 1:

                    cost = m[i][k]
                         + m[k+1][j]
                         + p[i-1] * p[k] * p[j]

                    if cost < m[i][j]:

                        m[i][j] = cost
                        s[i][j] = k

        return m, s

---

## Reconstructing the Optimal Parenthesization

The `s` table tells us where each matrix chain should be divided.

Define:

    printOptimalParenthesis(i, j)

If:

    i == j

then print:

    Ai

Otherwise:

    k = s[i][j]

and recursively print:

    (printOptimalParenthesis(i, k)
     ×
     printOptimalParenthesis(k+1, j))

This produces the complete optimal ordering.

---

## Example of DP Tables

For:

    A1 = 10 × 20
    A2 = 20 × 30
    A3 = 30 × 40

we have:

    p = [10, 20, 30, 40]

Initially:

    m[1][1] = 0
    m[2][2] = 0
    m[3][3] = 0

For two matrices:

    m[1][2] = 10 × 20 × 30
            = 6000

    m[2][3] = 20 × 30 × 40
            = 24000

For the complete chain:

    m[1][3]

There are two possible splits.

Split at `k = 1`:

    A1 × (A2 × A3)

    Cost = 0 + 24000 + (10 × 20 × 40)
         = 32000

Split at `k = 2`:

    (A1 × A2) × A3

    Cost = 6000 + 0 + (10 × 30 × 40)
         = 18000

Therefore:

    m[1][3] = 18000

and:

    s[1][3] = 2

So the optimal parenthesization is:

    ((A1 × A2) × A3)

---

## Correctness

The algorithm considers every possible position at which a matrix chain can be split.

For every subproblem `Ai ... Aj`, it calculates the cost of every possible split:

    Ai ... Ak | A(k+1) ... Aj

and chooses the minimum.

Because every possible parenthesization has a final split at some `k`, and the algorithm considers every possible `k`, the optimal parenthesization must be considered.

The DP table ensures that the optimal costs of smaller subchains are already available when calculating larger chains.

Therefore, `m[1][n]` contains the minimum possible number of scalar multiplications.

The `s` table stores the optimal split at every subproblem, allowing the complete optimal parenthesization to be reconstructed.

---

## Complexity Analysis

Let `n` be the number of matrices.

There are:

    O(n²)

DP subproblems.

For each subproblem, we may try up to:

    O(n)

possible split positions.

Therefore, the total time complexity is:

    O(n³)

The two tables `m` and `s` each require:

    O(n²)

space.

Therefore:

    Time Complexity  : O(n³)
    Space Complexity : O(n²)

---

## Key Idea

The problem is not about actually multiplying the matrices.

It is about finding the **best order in which to perform the multiplications**.

The main DP idea is:

    m[i][j] = minimum cost to multiply Ai ... Aj

and:

    s[i][j] = optimal split position

The recurrence is:

    m[i][j] =
        min {
            m[i][k] + m[k+1][j]
            + p[i-1] × p[k] × p[j]
        }

for:

    i ≤ k < j

The final answer is:

    m[1][n]

and the optimal ordering is obtained from:

    s[1][n]

### Final Complexity

    Time  : O(n³)
    Space : O(n²)
