# Triangle Coin Movement — Coordinate-Based Approach

## 📌 Problem Statement

Given an upward-pointing triangular arrangement of coins containing `n` rows, the goal is to transform it into an **inverted triangle** of the same size by moving the minimum possible number of coins.

The program represents every coin using a 2D coordinate:

```c
typedef struct {
    int x;
    int y;
} Point;
```

The original and target triangle configurations are generated mathematically, and the program determines which coins need to move.

---

## 🧠 Approach

The solution uses a **coordinate-based set comparison**.

### 1. Generate the Original Triangle

The original upward triangle is represented using:

```text
x >= 0
y >= 0
x + y <= n - 1
```

The program stores all of these coordinates in the `original[]` array.

The total number of coins is:

```text
n(n + 1) / 2
```

---

### 2. Generate the Target Triangle

The inverted triangle is shifted by:

```c
k = n / 3;
```

The target coordinates satisfy:

```text
-k <= x <= n-k-1
-k <= y <= n-k-1

x + y >= n - 1 - 2k
```

These coordinates are stored in the `target[]` array.

---

### 3. Find Coins That Need to Move

A coin does **not** need to move if its coordinate exists in both the original and target configurations.

The `contains()` function checks whether a particular point exists in an array.

```c
if (original[i] is not in target)
    source[ns++] = original[i];
```

These are the coins that must leave their original positions.

Similarly, the program finds the empty positions that need to be filled:

```c
if (target[i] is not in original)
    dest[nd++] = target[i];
```

These become the destination positions.

---

## 🔄 Moving the Coins

Once the source and destination coordinates are known, the program pairs them:

```text
source[0] → dest[0]
source[1] → dest[1]
...
```

Therefore, the number of required moves is the number of coins that are present in the original triangle but absent from the target triangle:

```text
moves = number of source positions
```

The program prints every movement as:

```text
(x1,y1) -> (x2,y2)
```

---

## 📐 Minimum Number of Moves

For this particular geometric transformation, the minimum number of moves is:

```text
floor(n(n + 1) / 6)
```

The program also prints this formula for verification:

```c
n * (n + 1) / 6
```

The result represents the number of coins whose positions differ between the two configurations.

---

## ⏱️ Complexity Analysis

There are approximately:

```text
O(n²)
```

points in each triangle because the number of coins is:

```text
n(n + 1) / 2 = O(n²)
```

However, the `contains()` function performs a **linear search**.

For each point in the original triangle, it may scan all target points:

```text
O(n²) × O(n²)
```

Therefore:

```text
Time Complexity:  O(n⁴)
Space Complexity: O(n²)
```

The `O(n²)` space is required to store the original triangle, target triangle, source positions, and destination positions.

---

## 💡 Important Observation

The main optimization idea is that **coins already occupying a required target position do not need to move**.

Therefore, instead of physically simulating every possible movement, the program simply compares:

```text
Original configuration
          ↓
     Find overlap
          ↓
Target configuration
```

The overlapping coordinates remain unchanged, while the remaining source coordinates are moved to the missing target coordinates.

---

## 📝 Summary

The program solves the triangle transformation by representing the arrangement as a collection of `(x, y)` coordinates.

It:

1. Generates the original triangle.
2. Generates the shifted inverted target triangle.
3. Finds the common positions.
4. Identifies the coins that must move.
5. Identifies the required destination positions.
6. Pairs source and destination positions.
7. Reports the minimum number of moves using:

```text
floor(n(n + 1) / 6)
```

The current implementation is straightforward but can be optimized significantly by using a more efficient data structure for coordinate lookup.
