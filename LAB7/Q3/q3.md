# 4-Peg Tower of Hanoi — Dynamic Programming

## 📌 Problem Statement

The **4-Peg Tower of Hanoi** is an extension of the classic Tower of Hanoi problem.

Given `n` disks and **4 pegs**, the objective is to move all disks from the source peg to the destination peg while following these rules:

1. Only one disk can be moved at a time.
2. A larger disk cannot be placed on top of a smaller disk.
3. All disks must eventually be moved from the source peg to the destination peg.
4. The goal is to minimize the total number of moves.

This implementation uses **Dynamic Programming** to determine an optimal way to divide the disks between the 4-peg and 3-peg solutions.

---

## 🧠 Approach

The algorithm is based on the **Frame-Stewart strategy** for the 4-peg Tower of Hanoi.

For `n` disks, choose a split point `k`:

* Move the top `k` smaller disks using **4 pegs**.
* Move the remaining `n-k` larger disks using the standard **3-peg Tower of Hanoi**.
* Move the `k` smaller disks onto the destination using **4 pegs** again.

Therefore, the total number of moves is:

```text
2 × dp[k] + (2^(n-k) - 1)
```

where:

* `dp[k]` = minimum moves required to transfer `k` disks using 4 pegs.
* `2^(n-k) - 1` = number of moves required to transfer `n-k` disks using 3 pegs.

The algorithm tries every possible value of `k` and chooses the one producing the minimum number of moves.

---

## 🔄 Dynamic Programming

The array:

```c
long long dp[MAX];
```

stores the minimum number of moves required for each number of disks.

The array:

```c
int split[MAX];
```

stores the optimal split point `k` for each `n`.

### State

```text
dp[n] = minimum number of moves required
        to move n disks using 4 pegs
```

### Base Cases

For zero disks:

```text
dp[0] = 0
```

For one disk:

```text
dp[1] = 1
```

---

## 📐 Recurrence Relation

For every `n >= 2`, the program tries all possible splits:

```text
1 <= k < n
```

The recurrence is:

```text
dp[n] = min(
    2 × dp[k] + (2^(n-k) - 1)
)
```

for all valid `k`.

In the code:

```c
long long moves =
    2 * dp[k]
    + ((1LL << (i - k)) - 1);
```

The expression:

```c
(1LL << (i - k))
```

computes:

```text
2^(i-k)
```

using a bit shift.

Whenever a better split is found, both the minimum number of moves and the corresponding split are stored:

```c
dp[i] = moves;
split[i] = k;
```

---

## 🏗️ Construction of the Move Sequence

After the DP table has been calculated, the `split[]` array contains the decisions needed to construct the move sequence.

The function:

```c
hanoi4()
```

recursively follows these decisions.

For `n` disks:

### Step 1 — Move `k` smaller disks

```c
hanoi4(k, source, auxiliary1, destination, auxiliary2);
```

The `k` smallest disks are moved from the source peg to the first auxiliary peg using the 4-peg strategy.

### Step 2 — Move the remaining disks

```c
hanoi3(n - k, source, destination, auxiliary2);
```

The remaining `n-k` disks are moved using the standard **3-peg Tower of Hanoi algorithm**.

The first auxiliary peg cannot be used here because it contains the smaller `k` disks.

### Step 3 — Move the smaller disks

```c
hanoi4(k, auxiliary1, destination, source, auxiliary2);
```

Finally, the `k` smaller disks are moved from the auxiliary peg to the destination using 4 pegs.

---

## 🔹 Standard 3-Peg Tower of Hanoi

The function:

```c
hanoi3()
```

implements the traditional recursive Tower of Hanoi algorithm.

For `n` disks:

```text
1. Move n-1 disks from source to auxiliary.
2. Move the largest disk from source to destination.
3. Move n-1 disks from auxiliary to destination.
```

Its recurrence is:

```text
T(n) = 2T(n-1) + 1
```

which gives:

```text
T(n) = 2^n - 1
```

This is used to move the larger `n-k` disks during the 4-peg algorithm.

---

## 🔢 Why Store `split[]`?

Calculating only `dp[n]` tells us the minimum number of moves, but it does not tell us **how to achieve that minimum**.

Therefore, the program stores:

```c
split[n]
```

which represents the value of `k` that produced the optimal solution for `n` disks.

The move-generation function later uses these stored decisions to reconstruct the sequence of moves.

This is a common Dynamic Programming technique:

```text
DP table       → stores optimal cost
Decision table → stores choices used to obtain the optimal cost
```

---

## 🧩 Algorithm

### Phase 1 — Calculate Minimum Moves

1. Initialize:

   ```text
   dp[0] = 0
   dp[1] = 1
   ```
2. For every number of disks `i` from `2` to `n`:

   * Initialize `dp[i]` to a large value.
   * Try every possible split `k`.
   * Calculate:

     ```text
     2 × dp[k] + 2^(i-k) - 1
     ```
   * Keep the minimum.
   * Store the corresponding `k` in `split[i]`.

### Phase 2 — Generate Moves

1. Start with `hanoi4(n, 1, 4, 2, 3)`.
2. Retrieve the optimal split from `split[n]`.
3. Recursively move the smaller disks using 4 pegs.
4. Move the remaining disks using 3 pegs.
5. Recursively move the smaller disks onto the destination.

## ⏱️ Complexity Analysis

### Dynamic Programming

There are `n` DP states.

For every state `i`, the program checks all possible split points:

```text
1 <= k < i
```

Therefore:

```text
Time Complexity:  O(n²)
Space Complexity: O(n)
```

The arrays `dp[]` and `split[]` require `O(n)` space.

### Move Generation

The actual number of moves can be exponential.

Therefore, generating and printing the complete sequence inherently requires time proportional to the number of moves:

```text
O(M)
```

where `M` is the total number of moves in the generated solution.

## 🔢 Peg Representation

The program uses four pegs:

```text
Peg 1 → Source
Peg 2 → Auxiliary
Peg 3 → Auxiliary
Peg 4 → Destination
```

The initial call is:

```c
hanoi4(n, 1, 4, 2, 3);
```

which means:

```text
Source      = Peg 1
Auxiliary 1 = Peg 2
Auxiliary 2 = Peg 3
Destination = Peg 4
```

## ⚠️ Implementation Notes

The program defines:

```c
#define MAX 50
```

and accepts:

```text
1 <= n < 50
```

The move count is stored using `long long` because the number of Tower of Hanoi moves grows exponentially.

The expression:

```c
1LL << (i - k)
```

uses a `long long` integer for the bit shift.

However, for sufficiently large `n`, even `long long` cannot represent the number of moves accurately. Therefore, the practical range is smaller than the declared maximum when exact move counts are required.

Also, printing the complete sequence for large `n` can produce an extremely large amount of output.

## 📝 Summary

The program solves the **4-Peg Tower of Hanoi** using Dynamic Programming combined with recursion.

The central idea is to divide the `n` disks into two groups:

```text
k smaller disks
n-k larger disks
```

The smaller group is handled using the 4-peg solution, while the larger group is handled using the standard 3-peg solution.

The recurrence:

```text
dp[n] = min(
    2 × dp[k] + 2^(n-k) - 1
)
```

is evaluated for every possible split `k`.

The optimal split is stored in `split[]`, allowing the program to reconstruct and print the corresponding sequence of moves.
