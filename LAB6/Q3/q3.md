# Longest Common Subsequence (LCS) Using Dynamic Programming

## Problem Statement

Implement the **Longest Common Subsequence (LCS)** algorithm using Dynamic Programming.

Given two strings, find:

1. The length of their longest common subsequence.
2. The actual longest common subsequence.

---

## Objective

Find the longest sequence of characters that appears in both strings in the same relative order.

The characters do not need to be adjacent in the original strings.

---

## What is a Subsequence?

A subsequence is a sequence obtained by deleting zero or more characters from a string without changing the order of the remaining characters.

For example, for the string `ABCDEF`:

- `ACE` is a subsequence.
- `BDF` is a subsequence.
- `ABF` is a subsequence.
- `AED` is not a subsequence because the order of characters is changed.

---

## Input

The program takes two strings as input:

1. First string
2. Second string

---

## Output

The program displays:

1. The length of the Longest Common Subsequence.
2. The Longest Common Subsequence itself.

---

## Approach

The problem is solved using **Dynamic Programming**.

Let:

`dp[i][j]`

represent the length of the LCS between:

- The first `i` characters of the first string.
- The first `j` characters of the second string.

For every pair of characters, there are two cases.

### Case 1: Characters are Equal

If:

`str1[i-1] == str2[j-1]`

then the character is part of the LCS.

Therefore:

`dp[i][j] = dp[i-1][j-1] + 1`

The value from the diagonal cell is used because both matching characters are included in the subsequence.

### Case 2: Characters are Different

If:

`str1[i-1] != str2[j-1]`

then one of the current characters must be excluded.

Therefore:

`dp[i][j] = max(dp[i-1][j], dp[i][j-1])`

This chooses the larger LCS obtained by excluding either the current character of the first string or the current character of the second string.

---

## Recurrence Relation

The complete recurrence relation is:

`if str1[i-1] == str2[j-1]`

`dp[i][j] = dp[i-1][j-1] + 1`

Otherwise:

`dp[i][j] = max(dp[i-1][j], dp[i][j-1])`

---

## Base Condition

If either string has length `0`, the LCS length is `0`.

Therefore:

`dp[0][j] = 0`

and:

`dp[i][0] = 0`

for all valid values of `i` and `j`.

---

## Algorithm

1. Read the first string.
2. Read the second string.
3. Find the lengths `m` and `n` of the two strings.
4. Create a DP table of size `(m+1) x (n+1)`.
5. Initialize the first row and first column with `0`.
6. Traverse the DP table from left to right and top to bottom.
7. Compare the current characters of both strings.
8. If the characters are equal, add `1` to the diagonal value.
9. If the characters are different, take the maximum value from the cell above and the cell to the left.
10. The value `dp[m][n]` gives the length of the LCS.
11. Start from `dp[m][n]` and backtrack through the table to construct the actual LCS.
12. If the characters are equal, add the character to the LCS and move diagonally.
13. If the characters are different, move toward the cell having the larger DP value.
14. Reverse the constructed sequence because backtracking generates it in reverse order.
15. Display the LCS length and the LCS.

---

## Finding the Actual LCS

The DP table gives the length of the LCS, but the question also requires displaying the subsequence.

To reconstruct it, start from:

`dp[m][n]`

and move backwards.

### If Characters Match

If:

`str1[i-1] == str2[j-1]`

then:

- Add the character to the LCS.
- Move diagonally to `dp[i-1][j-1]`.

### If Characters Do Not Match

Compare:

`dp[i-1][j]`

and:

`dp[i][j-1]`

If the value above is larger, move up.

Otherwise, move left.

Continue until either `i` or `j` becomes `0`.

Since the characters are collected from the end toward the beginning, the resulting sequence must be reversed before displaying it.

---

## Complexity Analysis

Let:

- `m` = length of the first string
- `n` = length of the second string

### Time Complexity

The DP table contains `(m+1) x (n+1)` entries.

Each entry requires constant time to calculate.

The backtracking process takes at most `O(m+n)` time.

Therefore, the overall time complexity is:

`O(m x n)`

### Space Complexity

The DP table requires:

`(m+1) x (n+1)`

memory locations.

Additional memory is required to store the LCS, but the DP table dominates the space requirement.

Therefore:

`O(m x n)`

---

## Comparison with Recursive Approach

The LCS problem can also be solved using recursion.

However, the plain recursive approach repeatedly solves the same subproblems and has exponential time complexity:

`O(2^(m+n))`

Dynamic Programming stores the results of previously solved subproblems and reduces the time complexity to:

`O(m x n)`

Therefore, Dynamic Programming is much more efficient than plain recursion for larger strings.

---

## Key Points

- LCS stands for **Longest Common Subsequence**.
- A subsequence does not require characters to be adjacent.
- The order of characters must remain unchanged.
- If two current characters match, use the diagonal DP value plus `1`.
- If they do not match, take the maximum of the top and left DP values.
- The final LCS length is stored in `dp[m][n]`.
- Backtracking is used to obtain the actual LCS.
- Time Complexity: `O(m x n)`
- Space Complexity: `O(m x n)`

---

## Conclusion

The Longest Common Subsequence problem can be efficiently solved using Dynamic Programming by dividing it into smaller overlapping subproblems.

The DP table stores the LCS length for different prefixes of the two strings. After constructing the table, backtracking is used to retrieve the actual longest common subsequence.

The algorithm has a time complexity of `O(m x n)` and a space complexity of `O(m x n)`.
