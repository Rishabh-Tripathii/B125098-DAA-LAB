# Merge K Sorted Arrays Comparison

## Overview

This C program compares two methods for merging `k` sorted arrays, each of size `n = 1000`, into a single sorted array.

- **Method 1:** Sequential merging, where arrays are merged one by one into a growing result.
- **Method 2:** Pairwise merging, where arrays are merged in rounds like a divide-and-conquer process.

For each value of `k` from 2 to 64, the program measures both the number of merge operations and the CPU time taken by each method. Pairwise divide-and-conquer merging is the standard efficient approach for merging multiple sorted arrays and runs in `O(S log k)` time where `S` is the total number of elements, while repeated sequential merging can take quadratic work in `k`. [1][2]

## What the Program Does

1. Allocates `k` sorted arrays.
2. Fills them with values arranged so each individual array is sorted.
3. Merges the arrays using Method 1 and records operations and time.
4. Merges the arrays using Method 2 and records operations and time.
5. Prints a table showing the comparison for each `k`.

## Output Format

The program prints a table with the following columns:

- `k`
- `Method 1 Operations`
- `Method 1 Time`
- `Method 2 Operations`
- `Method 2 Time`

Example structure:

```text
k        Method 1 Operations     Method 1 Time      Method 2 Operations     Method 2 Time
--------------------------------------------------------------------------------
2        ...                     ...                ...                     ...
4        ...                     ...                ...                     ...
8        ...                     ...                ...                     ...
...
64       ...                     ...                ...                     ...
```

## Method Descriptions

### Method 1: Sequential Merge

This method starts with the first array and repeatedly merges the next array into the current result.

- After the first merge, the result has size `2n`.
- After the second merge, the result has size `3n`.
- After the third merge, the result has size `4n`.

Because the intermediate merged array keeps growing, later merges become more expensive. This repeated work leads to a total complexity of `O(nk^2)` when there are `k` arrays of length `n`. [2][3]

### Method 2: Pairwise Merge

This method merges arrays in pairs during each round.

- Round 1 merges adjacent pairs.
- Round 2 merges the results of Round 1.
- The process continues until only one array remains.

Since the number of arrays is reduced by about half each round, there are `log k` rounds, and each round processes all elements once. That gives a total running time of `O(S log k)`, where `S = nk` is the total number of elements. [1][4]

## Time Complexity

Let:

- `k` = number of sorted arrays
- `n` = size of each array
- `S = nk` = total number of elements

| Method | Time Complexity | Reason |
|---|---|---|
| Sequential merge | `O(nk^2)` | The merged result grows after each step, causing repeated work. [2][3] |
| Pairwise merge | `O(S log k)` or `O(nk log k)` | Each round processes all elements once, across `log k` rounds. [1][4] |

Run the program with:


## Important Note

The implementation of `method2()` assumes that `k` is a power of 2. In this program, `k` takes the values 2, 4, 8, 16, 32, and 64, so that assumption holds. Pairwise divide-and-conquer merging reduces the number of arrays by roughly half each round, which is why powers of 2 fit the current implementation cleanly. [1][4]

If `k` were not a power of 2, one array could be left over in some round and would need to be carried forward to the next round.

## Interpretation

The program is expected to show that:

- Method 1 grows much faster as `k` increases.
- Method 2 scales much better for larger values of `k`.
- The time measurements should broadly follow the operation counts, though exact timing can vary by machine and compiler.

This matches the standard analysis of sequential merging versus divide-and-conquer merging for multiple sorted arrays. [1][4][2]
