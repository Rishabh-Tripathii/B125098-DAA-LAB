# README: Minimum Meeting Rooms

## Approach
The program finds the minimum number of meeting rooms required so that no two overlapping meetings use the same room.

It uses a **Greedy Approach with Sorting and Two Pointers**.

1. Sort the meeting start times in ascending order.
2. Sort the meeting end times in ascending order.
3. Use two pointers to track the next meeting start and the earliest meeting end.
4. If the next meeting starts before the earliest meeting ends, allocate a room.
5. Otherwise, a meeting has ended, so release a room.
6. Track the maximum number of rooms occupied simultaneously.

## Algorithm
1. Read the number of meetings and their start and end times.
2. Validate the input intervals.
3. If there are no meetings, print `0`.
4. Sort the start and end arrays independently using `qsort()`.
5. Initialize `i = 0`, `j = 0`, `rooms = 0`, and `maxRooms = 0`.
6. While `i < n`:
   - If `start[i] < end[j]`:
     - Increment `rooms`.
     - Increment `i`.
     - Update `maxRooms` if necessary.
   - Otherwise:
     - Decrement `rooms`.
     - Increment `j`.
7. Return and print `maxRooms`.

## Complexity Analysis

**Time Complexity: \(O(n\log n)\)**

- Sorting start times: \(O(n\log n)\).
- Sorting end times: \(O(n\log n)\).
- Traversing the arrays using two pointers: \(O(n)\).

Therefore, the overall time complexity is \(O(n\log n)\).

**Space Complexity: \(O(n)\)**

- Start and end arrays: \(O(n)\) space.
- Sorting may require additional implementation-dependent stack space.
- The two-pointer traversal uses \(O(1)\) auxiliary space, excluding sorting overhead.

Therefore, the overall space complexity is \(O(n)\), including the input arrays.

## Conclusion
The program efficiently calculates the minimum number of meeting rooms using sorted start and end times. The two-pointer technique identifies overlapping meetings in a single linear traversal after sorting.
