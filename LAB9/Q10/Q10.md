# README: Greedy Shortest Common Superstring

## Approach
The program constructs a superstring containing all the given strings as substrings using a **Greedy Algorithm**.

1. Calculate the maximum suffix-prefix overlap for every pair of distinct strings.
2. Select the pair with the largest overlap.
3. Merge the selected strings by appending only the non-overlapping portion of the second string to the first.
4. Remove the second string from the list.
5. Repeat until no positive overlap remains or only one string is left.
6. If multiple strings remain, concatenate them to produce the final superstring.

This greedy method attempts to minimize the length of the resulting superstring but does not guarantee the globally shortest possible superstring.

## Algorithm
1. Read the number of strings and the strings themselves.
2. While more than one string remains:
   - Initialize the maximum overlap to `-1`.
   - Examine every ordered pair of distinct strings.
   - Find the maximum suffix-prefix overlap using `findOverlap()`.
   - Record the pair with the largest overlap.
   - If the maximum overlap is zero or less, stop the merging process.
   - Merge the selected pair using `mergeStrings()`.
   - Remove the second string by shifting the remaining strings.
3. If multiple strings remain, concatenate them into the first string.
4. Print the resulting superstring and its length.

## Complexity Analysis

Let \(n\) be the number of input strings and \(L\) be the maximum length of an input string.

**Time Complexity: \(O(n^3L)\)**

- Finding the overlap between two strings takes \(O(L^2)\) in the worst case because `strncmp()` may compare up to \(L\) characters for each candidate overlap length.
- Examining all pairs takes \(O(n^2L^2)\) per iteration.
- The algorithm performs at most \(O(n)\) merging iterations, giving \(O(n^3L^2)\) for overlap searching.
- Merging and shifting strings also incur additional costs.

Therefore, the more accurate worst-case time complexity is **\(O(n^3L^2)\)**, assuming string lengths remain bounded by \(O(L)\) throughout the algorithm. Since merged strings can grow to length \(O(nL)\), a more conservative bound that accounts for their growth is \(O(n^4L^2)\).

**Space Complexity: \(O(nL)\)**

- The string array stores \(n\) strings, each with a fixed capacity of `MAX_LEN`.
- The algorithm uses only a constant number of additional variables for overlap calculations and indices.

Therefore, the auxiliary space complexity is \(O(1)\), while the total allocated storage for the string array is \(O(nL)\), treating \(L\) as the per-string capacity.

## Conclusion
The program uses a greedy strategy to combine strings with the maximum available overlap at each step. It produces a common superstring efficiently for small inputs, but the result is not guaranteed to be optimal.
