# Huffman Coding in C

## 📌 Overview

This project implements **Huffman Coding**, a greedy algorithm used for lossless data compression. Given a set of symbols and their frequencies, the program constructs an optimal prefix-free binary code and generates the corresponding **Canonical Huffman Codebook**.

The implementation uses a Min-Heap to construct the Huffman tree efficiently and assigns canonical codes based on the code lengths.

## 🎯 Objectives

* Implement the Huffman Coding algorithm in C.
* Construct a Huffman tree using a Min-Heap.
* Calculate the code length of each symbol.
* Generate canonical Huffman codes.
* Calculate the weighted path length and average encoded length.
* Analyze the time and space complexity of the algorithm.

## 🧠 Algorithm

The algorithm follows these steps:

1. Read the number of symbols and their frequencies.
2. Create a leaf node for each symbol.
3. Insert all nodes into a Min-Heap.
4. Extract the two nodes with the smallest frequencies.
5. Create a parent node whose frequency equals the sum of the extracted frequencies.
6. Insert the parent node back into the Min-Heap.
7. Repeat until a single Huffman tree remains.
8. Traverse the tree to calculate the code length of each symbol.
9. Sort the symbols by increasing code length and then by symbol value.
10. Generate canonical Huffman codes.
11. Display the codebook and calculate the weighted path length.

## 🌳 Example Huffman Tree

For the sample input, the tree is constructed by repeatedly combining the two smallest frequencies.

```text
                 (55)
                /    \
             (25)    (30)
             /  \    /  \
           C(12) D(13) (14) E(16)
                       /  \
                     A(5) B(9)
```

The branch labels `0` and `1` determine the binary code of each symbol in the Huffman tree. Canonical Huffman coding subsequently assigns standardized codes using the calculated code lengths.

## 📊 Canonical Huffman Codebook

| Symbol | Frequency | Code Length | Canonical Code |
| :----: | --------: | ----------: | :------------: |
|    C   |        12 |           2 |      `00`      |
|    D   |        13 |           2 |      `01`      |
|    E   |        16 |           2 |      `10`      |
|    A   |         5 |           3 |      `110`     |
|    B   |         9 |           3 |      `111`     |

Canonical Huffman coding sorts symbols by code length and then by symbol value. It assigns codes deterministically without requiring the original tree structure to be stored alongside the codebook.

## 📐 Complexity Analysis

Let `n` represent the number of distinct symbols and `Lmax` represent the maximum code length.

| Operation                        | Time Complexity |
| -------------------------------- | --------------- |
| Insert symbols into the Min-Heap | `O(n log n)`    |
| Construct the Huffman tree       | `O(n log n)`    |
| Calculate code lengths           | `O(n)`          |
| Sort symbols by code length      | `O(n log n)`    |
| Generate canonical codes         | `O(n × Lmax)`   |
| Display the complete codebook    | `O(n × Lmax)`   |

### Overall Time Complexity

The Huffman tree construction takes:

`O(n log n)`

Including code generation and output, the general worst-case time complexity is:

`O(n²)`

This is because the maximum code length can be proportional to the number of symbols.

### Space Complexity

The Huffman tree and Min-Heap require `O(n)` space.

Storing all canonical code strings requires `O(n × Lmax)` space.

Therefore, the total space complexity, including stored code strings, is:

`O(n × Lmax)`

## ⚠️ Limitations

* The program supports at most 256 distinct byte-sized symbols.
* Each symbol must be unique and have a positive frequency.
* The implementation is intended to generate a codebook; it does not compress or decompress files.
* Frequency sums and weighted costs must fit within the chosen integer types.

This project demonstrates how a greedy algorithm can construct an optimal prefix-free code from symbol frequencies. Using a Min-Heap makes Huffman tree construction efficient, while canonical coding provides a deterministic representation of the resulting codebook.
