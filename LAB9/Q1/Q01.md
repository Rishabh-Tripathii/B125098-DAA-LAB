# Fractional Knapsack with Deterioration Rate

## 📌 Overview

This project implements a variation of the **Fractional Knapsack Problem** using the C programming language.

In the traditional Fractional Knapsack Problem, items are selected according to their value-to-weight ratio. In this variation, the effective value density of each item decreases over time because of its deterioration rate.

The objective is to select items and determine their fractions while considering their changing value densities and the knapsack's capacity.

## 🎯 Problem Statement

Given `n` items, each item has:

* `vi`: Base value of the item.
* `wi`: Weight of the item.
* `λi`: Deterioration rate of the item.
* `W`: Maximum knapsack capacity.

The effective value density of an item at time `t` is:

$$
d_i(t) = \frac{v_i}{w_i} - \lambda_i t
$$

Where:

* `vi / wi` is the initial value density.
* `λi` is the deterioration rate.
* `t` represents the elapsed time.

The goal is to maximize the total value without exceeding the knapsack capacity.

## ⚙️ Algorithm Used

This implementation uses a **greedy selection heuristic**.

### Steps

1. Read the number of items and knapsack capacity.

2. Store each item's value, weight, and deterioration rate.

3. Initialize the current time and total value to zero.

4. Calculate the effective value density of each remaining item:

   $$
   d_i(t) = \frac{v_i}{w_i} - \lambda_i t
   $$

5. Select the remaining item with the highest positive effective density.

6. Take the complete item if it fits within the remaining capacity.

7. Otherwise, take only the fraction that fits.

8. Update the total value, remaining capacity, and elapsed time.

9. Repeat until the knapsack is full or no remaining item has positive effective density.

## 🔍 Dry Run

### Step 1: Initial Selection

Initially, `t = 0`.

| Item   | Effective Density |
| ------ | ----------------: |
| Item 1 |                12 |
| Item 2 |                25 |
| Item 3 |                20 |

Item 2 has the highest effective density.

* Weight selected: `4`
* Fraction selected: `1.0`
* Value added: `4 × 25 = 100`
* Remaining capacity: `10 − 4 = 6`
* Updated time: `t = 4`

### Step 2: Recalculate Effective Density

At `t = 4`:

Item 1:

$$
d_1(4) = 12 - 0.5(4) = 10
$$

Item 3:

$$
d_3(4) = 20 - 0.2(4) = 19.2
$$

Item 3 has the highest effective density.

* Weight selected: `6`
* Fraction selected: `1.0`
* Value added: `6 × 19.2 = 115.2`
* Remaining capacity: `0`
* Updated time: `t = 10`

### Final Result

| Metric             |          Result |
| ------------------ | --------------: |
| Selection order    | Item 2 → Item 3 |
| Total weight used  |              10 |
| Total value        |           215.2 |
| Remaining capacity |               0 |

## 📊 Complexity Analysis

Let `n` be the number of items.

### Time Complexity

In each iteration, the program scans all items to find the remaining item with the highest positive effective density.

There are at most `n` selection iterations.

Therefore:

$$
\boxed{O(n^2)}
$$

### Space Complexity

The program stores the details of all `n` items in an array.

Therefore:

$$
\boxed{O(n)}
$$

## ⚠️ Limitations

* The implementation assumes that one unit of weight takes one unit of time to consume.
* Effective density is evaluated at the start of each selection.
* The value calculation uses the density at the selection time.
* The greedy strategy is a heuristic and is not guaranteed to find the globally optimal solution for every input.
* The algorithm stops when the knapsack is full or all remaining items have non-positive effective density.

**Important:** The complexity analysis describes the provided greedy implementation. It does not establish the complexity of an algorithm guaranteed to find the global optimum.

## 👨‍💻 Conclusion

The Fractional Knapsack with Deterioration Rate problem introduces time-dependent value density into the traditional knapsack problem.

This implementation demonstrates how a greedy heuristic can select items based on their current effective density while respecting the capacity constraint. However, a separate mathematical proof and potentially a different algorithm are required to guarantee global optimality.
