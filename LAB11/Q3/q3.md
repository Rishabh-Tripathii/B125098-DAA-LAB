# Bidirectional BFS for Shortest Transformation Sequence in a Word Graph

## 1. Problem Statement

Given a dictionary \(D\) containing \(N\) unique words of equal length \(L\), a starting word \(A\), and a target word \(B\), find the minimum number of mutations required to transform \(A\) into \(B\).

A valid mutation consists of changing exactly one character of a word, such that the resulting word exists in the dictionary.

The transformation sequence must satisfy the following conditions:

- The sequence starts with \(A\) and ends with \(B\).
- Every intermediate word belongs to the dictionary.
- Every pair of consecutive words differs by exactly one character.
- The target word \(B\) must exist in the dictionary.
- If no valid transformation exists, return `-1`.

The constraints are \(N\leq 10^5\), \(L\leq 10\), and all words contain only lowercase English letters.

## 2. Approach

The problem can be modeled as finding the shortest path in an implicit, unweighted graph.

Each word represents a vertex, and two words are connected if they differ at exactly one character.

We use **Bidirectional Breadth-First Search (BFS)** to search simultaneously from the starting word \(A\) and the target word \(B\).

Two searches are maintained:

- Forward BFS, starting from \(A\).
- Backward BFS, starting from \(B\).

Each search maintains a distance array recording the minimum number of mutations from its respective starting point.

At every iteration, expand one complete BFS layer from the smaller frontier. This often reduces the number of explored words compared with ordinary BFS.

### Efficient Neighbor Generation

Instead of explicitly constructing every graph edge, generate neighbors dynamically:

1. Visit each character position in the current word.
2. Replace the character with each of the other 25 lowercase letters.
3. Check whether the resulting word exists in the dictionary using a hash table.
4. Process valid, unvisited neighbors.

When the two searches connect, combine their distances to obtain the transformation length.

If no connection is found, return `-1`.

## 3. Pseudocode

```text
BIDIRECTIONAL-BFS(A, B, D):

    If B is not in D:
        Return -1

    If A = B:
        Return 0

    Insert A into D if it is absent

    Initialize distA[word] = -1 for every word
    Initialize distB[word] = -1 for every word

    distA[A] = 0
    distB[B] = 0

    frontA = [A]
    frontB = [B]

    While frontA and frontB are not empty:

        If size(frontA) <= size(frontB):

            best = EXPAND-LAYER(
                frontA, distA, distB, D
            )

            If best is found:
                Return best

            Replace frontA with the next forward layer

        Else:

            best = EXPAND-LAYER(
                frontB, distB, distA, D
            )

            If best is found:
                Return best

            Replace frontB with the next backward layer

    Return -1


EXPAND-LAYER(frontier, distThis, distOther, D):

    nextFrontier = empty list
    best = infinity

    For each word u in frontier:

        For each character position i in u:

            Save the original character

            For each letter c from 'a' to 'z':

                If c equals the original character:
                    Continue

                Replace character i with c
                Let v be the modified word

                If v is not in D:
                    Continue

                If distOther[v] != -1:
                    best = min(
                        best,
                        distThis[u] + 1 + distOther[v]
                    )

                If distThis[v] == -1:
                    distThis[v] = distThis[u] + 1
                    Add v to nextFrontier

            Restore the original character

    Return best and nextFrontier
```

## 4. Algorithm

1. Store the dictionary in a hash table for efficient word lookup.
2. Verify that the target word exists in the dictionary.
3. Initialize forward and backward distance arrays with `-1`.
4. Set the starting word's forward distance and the target word's backward distance to `0`.
5. Expand one complete BFS layer from the smaller frontier.
6. Generate candidate neighbors by changing one character at a time.
7. Record distances for newly visited words and check whether the searches have connected.
8. Return the minimum combined distance when a connection is found.
9. If either frontier becomes empty without a connection, return `-1`.

## 5. Complexity Analysis

Let \(N\) be the number of dictionary words and \(L\) their common length.

**Time Complexity: Expected \(O(NL^2)\)**

Each word is visited at most once in each search direction. For every expanded word, up to \(25L\) candidate mutations are generated. Each candidate requires a hash-table lookup, with expected \(O(L)\) time for hashing and string comparison.

Therefore, the expected total time complexity is:

\[
\boxed{O(NL^2)}
\]

This bound assumes a hash table with expected constant-time probing behavior. In the worst case, excessive hash collisions can increase the running time.

**Space Complexity: \(O(NL)\)**

The dictionary stores \(N\) words of length \(L\). The hash table, distance arrays, and BFS frontiers require additional space proportional to the number of words.

Thus, the total space complexity is:

\[
\boxed{O(NL)}
\]

## 6. Conclusion

Bidirectional BFS efficiently solves the shortest word-transformation problem by searching from both endpoints and meeting in the middle. Dynamic neighbor generation avoids explicitly building the word graph, while a hash table enables efficient dictionary lookups. Under expected hash-table performance, the algorithm runs in \(O(NL^2)\) time and uses \(O(NL)\) space.
