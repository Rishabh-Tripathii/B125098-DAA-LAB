# Multi-Source BFS for Radius-Constrained Voronoi Cell Partitioning

## 1. Problem Statement

Given an unweighted, undirected graph \(G=(V,E)\), a set of \(K\) designated hub vertices \(H=\{h_1,h_2,\ldots,h_K\}\), and a non-negative integer radius \(R\), assign an ownership label to every vertex.

The objective is to assign each vertex to its nearest hub, provided that the vertex lies within the coverage radius \(R\).

For each vertex \(v\):

1. Calculate its shortest-path distance to every hub.
2. Find the minimum distance:

\[
d_{\min}(v)=\min_{1\leq i\leq K}\operatorname{dist}(v,h_i)
\]

3. If \(d_{\min}(v)>R\), or if the vertex is unreachable from every hub, assign `owner[v] = -1`.
4. Otherwise, assign the vertex to the nearest hub.
5. If multiple hubs are equally close, choose the hub with the smallest numerical index.

The output consists of the ownership label and the corresponding nearest-hub distance for every vertex.

## 2. Approach

The problem can be solved efficiently using **Multi-Source Breadth-First Search (BFS)**.

Instead of running a separate BFS from every hub, initialize a single BFS queue with all hub vertices. Since the graph is unweighted, BFS finds the shortest distance in terms of the number of edges.

Maintain two arrays:

- `dist[v]`: Minimum distance from any hub to vertex \(v\).
- `owner[v]`: Index of the hub that owns vertex \(v\).

Initially, set all distances and ownership labels to `-1`. Insert all hubs into the queue in increasing order of their hub indices. Each hub starts with distance `0` and its own index as its owner.

When an unvisited neighbor \(v\) of vertex \(u\) is discovered:

\[
\text{dist}[v]=\text{dist}[u]+1
\]

\[
\text{owner}[v]=\text{owner}[u]
\]

Then insert \(v\) into the queue.

Processing hubs in increasing index order, together with FIFO BFS and first-discovery assignment, ensures that ties between equally distant hubs are resolved in favor of the smallest hub index.

After BFS finishes, apply the radius constraint. If a vertex is unreachable or its minimum distance exceeds \(R\), set its ownership label to `-1`.

## 3. Algorithm

1. Initialize `dist[v] = -1` and `owner[v] = -1` for every vertex.
2. Insert all hub vertices into the queue in increasing hub-index order.
3. Set each hub's distance to `0` and its owner to its corresponding index.
4. While the queue is not empty:
   - Remove the front vertex \(u\).
   - Visit each adjacent vertex \(v\).
   - If \(v\) is unvisited:
     - Set `dist[v] = dist[u] + 1`.
     - Set `owner[v] = owner[u]`.
     - Insert \(v\) into the queue.
5. For every vertex \(v\):
   - If `dist[v] == -1` or `dist[v] > R`, set `owner[v] = -1`.
   - Otherwise, retain its assigned hub.
6. Output the ownership label and nearest-hub distance for every vertex.

## 4. Complexity Analysis

Let \(V\) be the number of vertices, \(E\) the number of edges, and \(K\) the number of hubs.

**Time Complexity: \(O(V+E)\)**

Building the adjacency list takes \(O(V+E)\) time. Multi-Source BFS visits each vertex at most once and examines each adjacency-list entry a constant number of times, requiring \(O(V+E)\) time. Applying the radius constraint takes \(O(V)\) time.

Since \(K\leq V\), the overall time complexity is:

\[
\boxed{O(V+E)}
\]

**Space Complexity: \(O(V+E)\)**

The adjacency list requires \(O(V+E)\) space. The distance array, ownership array, and BFS queue each require \(O(V)\) space.

Therefore, the total space complexity is:

\[
\boxed{O(V+E)}
\]

## 5. Conclusion

Multi-Source BFS efficiently partitions an unweighted graph into regions associated with the nearest hub. It avoids performing \(K\) separate BFS traversals, resolves equal-distance ties deterministically, and enforces the radius constraint after computing the nearest-hub distances. The algorithm achieves linear time and space complexity with respect to the graph size.
